# A13 operations fixtures (synthetic)

Hand-authored synthetic checkpoints shaped like the two native formats the
read-only operations adapters parse. Every value is invented; there is no real
batch state, run state, hashes, credentials or upstream content here.

| File | Native shape | Drives |
| --- | --- | --- |
| `cie-batch-checkpoint-stopped.json` | CIE batch runner `checkpoint.json` after a download-error stop (older snapshot) | stop/resume preservation, `stopped` state, superseded rows |
| `cie-batch-checkpoint-running.json` | CIE batch runner `checkpoint.json` while running (newer snapshot, no stop fields) | `in_progress` state, missing fields stay `None` |
| `ielts-run-checkpoint-ok.json` | `ielts-run-checkpoint/1` healthy run | `ok` state, counters/sources verbatim |
| `ielts-run-checkpoint-ok-stale.json` | `ielts-run-checkpoint/1`, same synthetic run, earlier `updated_at` | stale summary superseded, never overriding the newer node |
| `ielts-run-checkpoint-partial.json` | `ielts-run-checkpoint/1` with consecutive 5xx and a blocked source | `partial_failure`, counters never zeroed, blocked source visible |
| `unsupported-checkpoint.json` | neither native format | `unknown` row with explicit problems, never dropped |

`PROVENANCE.json` records each fixture with its sha256 and byte count and is
generated by `integration-staging/tools/a13_capture_fixtures.py`; run that
tool with `--check` to verify without writing.
