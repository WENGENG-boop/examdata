# CIE 试卷纯算法切题成图 —— 设计文档

本文件是本项目（`cie-question-crops/`）的设计与验证依据。全部实现为新增代码，
不改动工作区中任何既有项目、批次、索引或数据。

## 1. 背景与目标

- 场景：CIE QP 的文字层是**乱码**（字形被一致替换，例如 `~` 表空格、`¦` 表 `1`、
  `ą` 表 `0` 等）。不能依赖读取文字内容，也不能使用 OCR / 模型。
- 目标：**纯算法**（只读 PDF 文字层 span 的坐标与字形结构）把每道题定位、
  裁剪、渲染成 PNG 图片交付。乱码不返回具体题目的文字，直接返回题目的图片。
- 范围：只做「切题成图」；不做文字还原、不做语义解析、不联网。

## 2. 输入 / 输出

- 输入：一份 QP PDF。
  示例样本：`C:/Users/weo/Desktop/api/examdata/tmpwork/paperqa-live/python-0/9709_m26_qp_12.pdf`
  （16 页，Letter 612×792pt，rotation=0）。
- 输出（默认 `<本项目>/out/<pdf 文件名>/`，全部落在本项目目录内）：
  - `crops/qNN.png`       整题合成图；多页题按页纵向拼接
  - `crops/qNN-pNN.png`   多页题的逐页分图
  - `crops/manifest.json` 每题页码、y 区间、小题标记与自检结果
  - `viewer.html`         查看页（`--no-viewer` 关闭）
- 依赖：仅 `pymupdf`（+ Python 标准库）。**不 import `cie-location-batch` 的任何代码**，
  本项目自包含、可独立运行。

## 3. 算法总览（与文字内容无关）

1. **span 提取**：逐页取 `get_text("dict")` 的非旋转（`dir≈(1,0)`）文字 span，
   记录 `(x0,y0,x1,y1,text)`；跳过纯空格 span。乱码不影响坐标。
2. **题号 token 检测**：左栏、页顶的短 span：
   `x0∈[70,76]`、`y0<82`、`x1≤92`、剥掉空格字形后长度 1–3。按 (页, y0) 排序。
3. **小题标记检测**：`x0∈[92,97]`、`x1≤118`、长度恰 3 的 span 作为候选；
   统计每个候选的「首字形+尾字形」配对出现次数，**≥2 次的才保留**（噪声候选被过滤）。
   乱码是一致替换，同一标记（如 `(a)`）在整卷重复出现，配对计数不受乱码影响。
   保留的候选按首次出现顺序分配字母 a,b,c…。
4. **页面签名（点线行）**：长度 ≥30 且不同字形 ≤3 的长重复行（答题点线）：
   - 缩进列 `x0∈[88,132]`（实测 93.7 / 115.1）→ 题内答题区（续页特征）；
   - 整栏起 `x0≤80`（实测 72.4）→ 卷尾附加页特征。
5. **裁剪框推导**：见第 5 节。
6. **题目分段**：见第 6 节。
7. **渲染**：见第 7 节。
8. **自检 6 项**：见第 8 节；不过不静默，全部写入 manifest 与终端输出。
9. **manifest + 查看页**：manifest 记录来源 PDF 的 sha256、生成时间、裁剪框、
   每题明细与自检结果；查看页把合成图按序排成 HTML。

## 4. 版面常量（9709/2026/Mar/12 实测）

| 常量 | 值 | 含义 |
| --- | --- | --- |
| `TOKEN_X0` | (70.0, 76.0) | 题号列 x0 |
| `TOKEN_X1_MAX` | 92.0 | 题号 span 右界 |
| `TOKEN_Y_MAX` | 82.0 | 题号只在页顶 |
| `TOKEN_GLYPHS` | (1, 3) | 剥空格后题号字形数 |
| `MARKER_X0` | (92.0, 97.0) | 小题标记列 x0 |
| `MARKER_X1_MAX` | 118.0 | 小题标记右界 |
| `MARKER_GLYPHS` | 3 | `(a)` 类标记字形数 |
| `MARKER_PAIR_MIN` | 2 | 首尾字形成对的最小出现次数 |
| `CONTENT_Y` | (50.0, 735.0) | 内容区 y 范围（页顶条码/页码与页脚在其外） |
| `CROP_PAD_X` | 10.0 | 裁剪框左右留白 |
| `TOP_FLOOR` | 56.5 | 上界不低于页顶行下沿 |
| `TOP_GAP` | 2.0 | 上界与首题号 y0 的间隙 |
| `BOTTOM_GAP` | 0.7 | 下界与页脚顶的间隙 |
| `DOT_MIN_GLYPHS` / `DOT_MAX_KINDS` | 30 / 3 | 长重复行判定 |
| `DOT_X0_INDENT` | (88.0, 132.0) | 题内点线缩进列 |
| `DOT_X0_FULLWIDTH` | 80.0 | 附加页点线整栏起 |
| `DOT_ROWS_MIN` | 5 | 判定「点线页」的最少行数 |
| `EDGE_PX` / `INK_DARK` / `INK_RANGE` | 9 / 200 / (0.0005, 0.20) | 图像自检参数 |
| `ARTIFACT_X` / `ARTIFACT_Y` | (55,556) / (50,745) | 页边印刷标记/灰条带（不算内容图形） |
| `MAX_PAGE_PT` | 14000.0 | 合成图高度上限（PyMuPDF 单页限制附近） |

常量按本样本实测；换版式时由自检（`edges_clean` / `drawings_within_box` /
`subparts_contiguous` 等）兜底报警，而不是静默切错。

## 5. 裁剪框推导

设首题 token 在第 `p0` 页（0 基）：

- 内容区：第 `p0` 页起所有 `50 < y0 < 735` 的 span → `xs0=min(x0)`、`xs1=max(x1)`、
  `ys1=max(y1)`。
- 页顶行（条码/页码）：所有页 `y0 < 55` 的 span → `top_y1=max(y1)`（缺省 57.0）。
- 页脚行：**从 `p0` 页起**所有 `y0 > 730` 的 span → `foot_y0=min(y0)`（缺省 None）。
  （注意：首页说明页底部有非页脚文字，页脚扫描必须从首题页起，否则下界误判。）
- 上界：`top = min(max(top_y1 + 0.8, TOP_FLOOR), tmin - TOP_GAP)`，`tmin` 为首题号 y0。
- 下界：`bot = min(ys1 + 0.8, foot_y0 - BOTTOM_GAP)`（无页脚时取 `ys1 + 0.8`）。
- 左右：`left = xs0 - CROP_PAD_X`、`right = xs1 + CROP_PAD_X`。

样本实测：`left=62.4 top=56.9 right=550.8 bottom=735.2`。

## 6. 题目分段规则

对每个题号 token（第 i 题，0 基）：

- **同页下一题**：下一 token 与本题同页 → 本题结束于 `下一题号 y0 - TOP_GAP`
  （不低于 `top + 10`）。
- **跨页题**：下一 token 在后面的页 → 本题覆盖 `[本题页, 下一题页-1]`，每页取 `top..bot`。
- **末题**（无下一 token）：`end = max(本题页, 本题各小题标记所在页)`，再向后
  吞并「缩进点线 ≥ `DOT_ROWS_MIN` 行」的续页。
- **小题归属**：标记 `(页, y0)` 落在本题 token 与下一 token 之间即归本题。
- **附加页排除**：卷尾「整栏点线（`x0≤80`）且无缩进点线」的页面不属于任何题
  （样本中第 16 页），由 `nothing_after_last` 自检确认。

样本实测：11 题（Q1 p3 … Q9 p11，Q10 p12-13，Q11 p14-15；p16 附加页排除）；
19 个小题标记（Q2–Q8 各 2、Q9=0、Q10=2、Q11=3）。

## 7. 渲染与像素口径

- `zoom` 默认 3.0；像素尺寸由 PyMuPDF 像素网格决定（实测：宽 488.4pt×3 → 1466px）。
- **合成图**：新建一页 PDF（宽 = 裁剪框宽，高 = `round(Σ段高, 2)`），逐段
  `show_pdf_page(clip=...)` 纵向拼接后 `get_pixmap`；高度 = `ceil(round(Σ段高,2) × zoom)`
  （本例：单页 678.3pt×3 → 2035px；双页 1356.6pt×3 → 4070px）。
- **分页图**：原页直接 `get_pixmap(clip=裁剪框×rotation_matrix)`；裁剪矩形按像素边界
  吸附（floor/ceil），每页比合成图多 1px 白边（本例 678.3pt → 2036px；四边无墨自检
  已确认多出的 1px 为白，不含内容）。
- **口径固定（决策记录）**：原型与工具曾出现 1px 差异（2035 vs 2036），根因已定位：
  合成图按整页高度取 `ceil`，分页图按裁剪矩形像素吸附。两种口径均与既有参考实现
  （`cie-location-batch/tools/crop_questions.py` 在样本卷上的运行产物）逐字节一致
  （15/15 图 sha256 相同），故按现状固定为验收口径，由测试锁定尺寸：
  合成图 单页 1466×2035 / 双页 1466×4070；分页图 1466×2036。
- 合成高度 > `MAX_PAGE_PT` 时不拼合成图（只出逐页分图）并记警告。
- 旋转页（`rotation≠0`）：按 `rotation_matrix` 处理并记警告，需人工复核。

## 8. 自检（6 项，全部写入 manifest）

1. `subparts_contiguous`：每题的小题字母恰为 a,b,c…（连续、从 a 起）。
2. `marker_pair_single`：存活（≥2 次）的字形对唯一；并报告过滤掉的噪声候选数。
3. `edges_clean`：每张输出图四边 `EDGE_PX` 像素带内无深色墨迹（`<200`）。
4. `ink_sane`：每张输出图整图墨迹占比在 `INK_RANGE` 内（防全黑/全空）。
5. `drawings_within_box`：内容矢量图形（图表等）完整落在裁剪框内；
   页边带（`ARTIFACT_X/Y`）内的印刷标记/灰条不算内容图形。
6. `nothing_after_last`：最后一题之后只有附加页/空页；若出现含内容页则报警。

自检不过 → manifest 中 `ok=false` + 警告列表；`--strict` 时进程返回码 2。

## 11. 决策记录

- **为什么不用 OCR/模型**：用户明确要求纯算法；乱码是字形一致替换，坐标几何不受影响。
- **为什么字形对 ≥2 过滤**：标记候选含噪声（同列 3 字形 span），真实标记在多题重复出现。
- **为什么页脚扫描从首题页起**：第 1 页（说明页）底部有 y0=731.6/733.0 的文字，
  若从第 1 页扫描会把下界压到 733.0 以下，裁掉题目内容。
- **1px 口径**：见第 7 节；合成图与分页图的像素吸附差异（2035 vs 2036）为 PyMuPDF 既定行为，与参考实现逐字节一致，由测试锁定，不再视为未决问题。
- **只新增**：所有产物写入本项目 `out/` 目录；工具不写本项目以外的任何路径。
